## 系统架构：四区 × 三层 × 敏感度

```
维度1：四区（按工作角色分目录）
  work/{产品线}/   项目工作（按产品线隔离，项目完结整体归档）
  knowledge/       通用知识：方法论/规范/竞品档案/行业认知（跨项目复用）
  style/           风格层（AI 分身风格种子，始终加载）
  archive/         完结项目归档区（终态冻结）

维度2：生命周期（仅 work/ 与 knowledge/ 内部三层）
  context/    已确认的事实
  workspace/  进行中的工作
  drafts/     想法和素材
  知识单向流动：drafts/ → workspace/ → context/，拿不准进 drafts/
  style/ 为扁平风格文件、archive/ 为终态归档，不套三层

维度3：敏感度
  🟢 可公开 / 🟡 公司工作内容（默认级，仅私有远程）/ 🔴 红线机密（不入 Git + 不入索引）
```

## 目录结构

| 目录 | 用途 | 敏感度 |
|------|------|--------|
| `work/{{产品线}}/` | 项目工作——按产品线隔离，每条产品线独立子目录 | 🟡 |
| `knowledge/` | 通用知识——方法论、设计规范、竞品档案、行业认知 | 🟡 |
| `style/` | 风格层——思维、沟通、审美（AI 分身种子，**始终加载**） | 🟡 |
| `archive/` | 完结项目的整体归档区 | 🟡 |

（🟡 为默认级；具体文件按实际内容可标 🟢（公开行业文章收藏、已对外发布的内容）或 🔴（红线机密），定级规则见下方「敏感度红线」。）

## AI 行动规则（最优先执行）

### 1. 会话开始必做

- 读 `style/` 三个文件（thinking.md / communication.md / taste.md）加载风格——**style/ 始终加载，无论什么任务**（文件尚未创建时跳过此步，不报错；升级台阶 4 时填充）
- 读根索引 Recent 区，一句话了解最近动态

### 2. 索引规则（硬约束）

- Read 任何 .md 文件前，先检查父目录的 AGENTS.md 是否索引了它
- 未索引的文件视为「不可见」——不读、不引用、不基于其内容回答
- 「已索引」的两种合法形态：**逐文件索引**（curated 白名单，仅列出者可见，默认形态）；**目录级索引**（目录行声明整目录可见，适合竞品素材、行业报告这类成品参考集——AI 可在该目录内自由检索，免逐文件登记）
- 索引正文不写死文件计数；要数字现场数或跑对账脚本
- 新增 / 删除文件必须同步更新父目录 AGENTS.md；新文件在 Recent 区追加登记
- 越往上层越抽象（全局规则），越往下层越具体（文件清单）

### 3. 敏感度红线

| 敏感度 | 含义 | AI 行为约束 |
|---|---|---|
| 🟢 | 可公开（公开行业文章收藏、已对外发布的内容） | 正常读写，可对外输出 |
| 🟡 | 公司工作内容（**默认级**） | 可读写、可提交私有远程（仅限工作需要的人访问）；禁止任何公开渠道输出 |
| 🔴 | 红线机密 | 不入 Git（.gitignore 排除）+ 不入索引（对 AI 不可见）；最稳妥物理隔离存库外。永不输出到任何渠道 |

禁止跨级污染：🟡/🔴 内容不得写入 🟢 文件。诚实提醒：.gitignore 只管 Git，管不住 AI 读文件系统——🔴 的「不入索引」是纪律约束，不是技术隔离。

### 4. 信息安全红线（优先于一切产出任务）

- 会话本身不保密：AI 读库意味着内容随会话发送给模型服务商
- 红线内容（核心经营数据、薪酬信息、未公开的合作与商务条款等）不入库、不进会话，遵守公司信息安全规定
- 对抗审查、反向同步云端等外发动作，先确认符合公司安全口径再做
- 拿不准先确认安全口径，宁可慢不可错

### 5. 动作纪律

- 重要动作提议 → 用户确认再执行；删除、git 推送、批量移动、覆盖类必须先问
- 基于库回答问题默认只读；高价值新理解提议回填，用户点头才写
- 库内产出的团队共识结论，提议用户反同步回飞书——本地 md 是 AI 工作的输入真相源，飞书仍是公司正式文档源，两者分工不打架；反向同步走「提议→确认」

### 6. 入库纪律（「记录这个」类存储指令的硬约束）

- 动手前先报**四选一**分诊：新货（库里没有同主题，走完整入库）/ 补货（已有同主题，更新旧文件或新增+交叉引用）/ 有矛盾（与库内结论冲突，双方都保留+就地标注「待裁决」，Recent 同步记一行）/ 没营养（无实质价值，只存原文+记一笔——这是合法出口，绝不强行整理）
- 新文件只追加 Recent 区（一行日期+文件名+一句话），不改正文清单；攒满 20 条提醒用户收编
- 索引正文不写死文件计数，要数字现场数或跑对账脚本

## 知识流动（单向提炼）

知识在各区产生，向通用层和风格层提炼，不反向流动：

```
work/{{产品线}}/ ──(项目完结提炼)──► archive/（原样冻结，剔除🔴）＋ 可复用方法论汇入 knowledge/
work/{{产品线}}/ ──(持续提炼)──► knowledge/ 方法论与规范
所有领域 ──(风格特征)──► style/*.md
```

提炼一律先提议、用户确认再执行。

## 文档规范

- 命名：持久内容用 `{topic}.md`（如 profile.md）；时间相关用 `{date}-{topic}.md`（如 2026-01-15-周会.md）
- 图片：存 `assets/{文档标识}/`，命名 `{章节关键词}-{序号}.png`，不散放在 assets/ 外；图片不入 Git（.gitignore 排除 `**/assets/`），换机通过公司认可的方式单独同步
- 内部链接用标准 Markdown 相对路径；重命名 / 移动文件前先查引用并同步更新索引与正文链接
