## 系统架构：四区 × 三层 × 两层敏感度

```
维度1：四区（按工作角色分目录）
  work/{产品线}/   项目工作（按产品线隔离，项目完结整体归档）
  knowledge/       通用知识：方法论/规范/竞品档案/行业认知（跨项目复用）
  style/           风格层（AI 分身风格种子，始终加载）
  archive/         完结项目归档区（终态冻结）

维度2：生命周期（仅 work/ 与 knowledge/ 内部三层）
  context/    已确认的事实
  workspace/  进行中的工作
  drafts/     想法和素材
  知识单向流动：drafts/ → workspace/ → context/，拿不准进 drafts/
  style/ 为扁平风格文件、archive/ 为终态归档，不套三层

维度3：敏感度（两层）
  🔴 红线：不入库、不进会话、不入 Git、不入索引（最稳妥物理隔离存库外）
  默认级：其余全部内容，照常进 Git；远程用认可载体（工作场景）/私有仓库（个人场景）
```

## AI 行动规则（最优先执行）

### 1. 会话开始必做

- 读 `style/` 三个文件（thinking.md / communication.md / taste.md）加载风格——**style/ 始终加载，无论什么任务**（标「待启用」或文件尚未创建时跳过此步，不报错）
- 读根索引 Recent 区，一句话了解最近动态

### 2. 索引规则（硬约束）

- Read 任何 .md 文件前，先检查父目录的 AGENTS.md 是否索引了它
- 未索引的文件视为「不可见」——不读、不引用、不基于其内容回答
- 「已索引」的两种合法形态：**逐文件索引**（curated 白名单，仅列出者可见，默认形态）；**目录级索引**（目录行声明整目录可见，适合竞品素材、行业报告这类成品参考集——AI 可在该目录内自由检索，免逐文件登记）
- 索引正文不写死文件计数；要数字现场数或跑对账脚本
- 新增 / 删除文件必须同步更新父目录 AGENTS.md；新文件在 Recent 区追加登记
- 越往上层越抽象（全局规则），越往下层越具体（文件清单）

### 3. 敏感度（两层）

| 级别 | 含义 | AI 行为约束 |
|---|---|---|
| 🔴 红线 | 不能让外部模型服务商看到的内容：密码密钥、证件号码、薪酬信息、未公开的合作与商务条款、{{所在组织规定的保密信息}}等 | 不入库、不进会话；不入 Git（.gitignore 排除）且不入索引（对 AI 不可见）；最稳妥物理隔离——存在知识库之外 |
| 默认级 | 其余全部内容（入库存档正是建库的目的） | 照常读写、照常进 Git；远程载体：工作场景用组织认可载体，个人场景用私有仓库。推远程前先确认载体 |

红线判断只有一条：这条内容能不能让外部模型服务商看到？不能的就是 🔴。

诚实提醒：.gitignore 只管 Git，管不住 AI 读文件系统——🔴 的「不入索引」是纪律约束，不是技术隔离；最敏感的内容直接存库外。

### 4. 三条安全规矩（第一天就立，优先于一切任务）

1. **红线内容不入库、不进会话**——会话本身不保密：AI 读库意味着内容随会话发送给它背后的模型服务商
2. **拿不准先确认安全口径**——某类内容能不能用 AI 处理拿不准，先向我确认再动手
3. **推远程前确认用的是认可载体（工作场景）/私有仓库（个人场景）**

对抗审查、反向同步云端等外发动作，同样先确认安全口径再做。

### 5. 动作纪律

- 重要动作提议 → 用户确认再执行；删除、git 推送、批量移动、覆盖类必须先问
- 基于库回答问题默认只读；高价值新理解提议回填（链接来源文件，原话与推断分开标注），用户点头才写
- 库内产出的团队共识结论，提议回流到团队平台（如飞书）——本地 md 是 AI 工作的输入真相源，团队平台是团队正式文档源，两者分工不打架；回流走「提议→确认」

### 6. 入库纪律（「记录这个」类存储指令的硬约束）

- 动手前先过**红线预拦**：疑似 🔴 的素材不入库、不登记，提醒我物理隔离存放
- 再报**四选一**分诊：新货（库里没有同主题，走完整入库）/ 补货（已有同主题，更新旧文件或新增+交叉引用）/ 有矛盾（与库内结论冲突，双方都保留+就地标注「待裁决」，Recent 同步记一行）/ 没营养（无实质价值，只存原文+记一笔——这是合法出口，绝不强行整理）
- 新文件只追加 Recent 区（一行日期+文件名+一句话），不改正文清单；索引正文不写死文件计数

## 知识流动（单向提炼）

知识在各区产生，向通用层和风格层提炼，不反向流动：

```
work/{{产品线}}/ ──(项目完结提炼)──► archive/（原样冻结，剔除🔴）＋ 可复用方法论汇入 knowledge/
work/{{产品线}}/ ──(持续提炼)──► knowledge/ 方法论与规范
所有领域 ──(风格特征)──► style/*.md
```

提炼一律先提议、用户确认再执行。

## 文档规范

- 命名：持久内容用 `{topic}.md`（如 profile.md）；时间相关用 `{date}-{topic}.md`（如 2026-01-15-周会.md）
- 图片：存 `assets/{文档标识}/`，命名 `{章节关键词}-{序号}.png`，不散放在 assets/ 外；图片不入 Git（.gitignore 排除 `**/assets/`），换机通过认可的方式单独同步
- 内部链接用标准 Markdown 相对路径；重命名 / 移动文件前先查引用并同步更新索引与正文链接
