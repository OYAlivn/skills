# kos-starter — 个人工作知识库起步引导 + 成长托管（公司场景版）

一句话定位：帮没用过 AI agent 的同事，30 分钟搭出「让 AI 一开门就认识你和你的工作」的最小知识库，并在后续使用中轻量托管、按成长节奏引导升级到 AI 分身。

目标用户是中文小白——解释每一步都回答「为什么要做这件事」，术语首次出现时用一句话说清。本 skill 不是全功能知识库管家，用户长大后的去处见文末「边界与让位」。

配套方法论：《个人AI工作流搭建方案》（公司场景版，见本 skill 的 `docs/` 目录）——方案讲为什么，skill 是执行层，两者口径一字不差。

## 小白沟通守则

1. 术语第一次出现就用一句话解释（索引 = 给 AI 看的目录说明书；入库 = 把素材存进库；Git = 记录每次修改、可回滚的版本管理工具）
2. 一次只让用户做一个动作，做完确认再进下一个；用户卡住时给选项，不出开放题
3. 每个要求都带 why——用户理解了才会长期执行，背下来的规矩活不过一周
4. 能示范的直接示范：与其解释 Recent 区是什么，不如当场登记一条给他看
5. 不替用户做决定（尤其升级时机、删除动作），AI 给信息和选项，用户拍板

## 三条核心理念（所有模式的共同前提）

1. **输入 = 命令 + 上下文**：AI 的输出质量取决于它回答前读到了什么。上下文（你是谁、你在做什么、规矩有哪些）是可复用资产——写一遍，之后无数次对话直接复用
2. **内容比结构重要**：先有鸡再修鸡窝。一个内容丰富但目录丑陋的库，胜过结构精美但空空如也的库
3. **拿不准进 drafts**：错存可以事后升级，错放进「已确认事实」会污染整个库的判断

三个理念分别回答：为什么要建库（上下文是资产）、为什么先建最小版（内容优先）、拿不准怎么办（进 drafts）。用户问「凭什么信这套」时，按这个顺序讲。

## 信息安全红线（公司场景，优先于一切任务）

1. **会话本身不保密**：AI 读库意味着内容会随会话发送给它背后的模型服务商。库文件不出你的电脑，但进了会话的内容就是发出去了
2. **红线内容不入库、不进会话**：核心经营数据、薪酬信息、未公开的合作与商务条款等公司红线内容，一律不入库、不进会话，遵守公司信息安全规定
3. **外发动作同样受约束**：双 AI 对抗审查（内容发给第二个 AI）、反向同步云端等外发动作，先确认符合公司安全口径再做
4. **拿不准先确认安全口径**：某类内容能不能用 AI 处理拿不准时，先确认再动手——宁可慢，不可错

建库第一天就立的三条安全规矩（①红线内容不入库不进会话 ②拿不准先确认安全口径 ③推远程前确认用的是公司认可载体）见 Mode 1 手册与 `templates/AGENTS-mini.md`，口径与「统一口径」区一致。

## 三个模式

| 模式 | 干什么 | 触发信号 | 执行手册 |
|---|---|---|---|
| Mode 1 BUILD 搭建引导 | 30 分钟搭出最小版工作知识库 | 首次搭建；「搭建知识库」「建KOS」「30分钟知识库」「整理笔记给AI用」 | 读 `references/build-guide.md` 全文再动手 |
| Mode 2 USE 日常入库 | 「记录这个」标准入库流程 | 「记录这个」「保存这个」「存到知识库」；用户粘贴内容表达存储意图 | 读 `references/ingest-basics.md` |
| Mode 3 GROW 升级体检 | 阶段性升级 + 体检 | 「升级知识库」「体检」「知识库乱了」；或 Mode 2 的成长触发条件命中 | 读 `references/upgrade-path.md` |

进入任一模式前，先把对应手册读完，再按手册执行。手册里有的细节以手册为准，本文件只管路由和原则。

各模式的验收产出：

- Mode 1：文件夹 + 定制版 `AGENTS-mini.md` 索引（含第一天三条安全规矩）+ 通过背景测试和入库测试
- Mode 2：素材落位 + 索引登记 + Recent 流水账 + 一句话确认
- Mode 3：定位当前台阶 + 完成该台阶动作 + 收尾台账（Recent 登记 / commit / 对账报告）+ 重做一次背景测试（升级不能把「AI 认识你」弄丢）

模式可以连续发生（先 BUILD 再当场 USE），但一个时刻只做一个模式的事——不要在搭建中途顺手入库，也不要在体检时顺手改结构。

## 库的判定与质检

判断「有没有库」：目标文件夹根目录是否存在 AGENTS.md。**存在 ≠ 合格**——先读一眼内容：缺规矩区或 Recent 区的（用户手写或他工具生成的「野索引」），先提议按 `templates/AGENTS-mini.md` 补齐这两区（既有内容不动），用户同意并补齐后再进日常流程；AGENTS.md 不存在才算没库。这一步防的是：拿乱索引当权威纪律加载，后续流程全部对不上号。

## 通用纪律（三个模式都必须遵守）

1. **新文件必登记索引**：写完任何新文件，同步更新父目录 AGENTS.md（清单或 Recent 区；目录级索引声明的目录内免逐文件登记）。未索引的文件对 AI 不可见——等于没存
2. **重要动作提议→用户确认再执行**：删除、覆盖、批量移动类动作，先说清方案，用户点头再做。日常读写不用逐步请示
3. **索引正文不写死文件数**：只列文件名，不写「共 N 篇」。用户要数字，现场数或跑脚本——数字写死必漂移，漂移一次全场失信
4. **疑似红线先拦一道**：任何输入疑似红线内容——不只入库，分析、改写、翻译等请求同样算——先提醒用户确认安全口径再继续

### 统一口径（本文件与三个 references 必须一致，不得漂移）

- **四区结构**：`work/{产品线}/`（项目工作，按产品线隔离，项目完结整体归档）、`knowledge/`（方法论、规范、竞品档案、行业认知，跨项目复用）、`style/`（风格层，始终加载）、`archive/`（完结项目归档区）。三层生命周期（drafts/workspace/context）只套在 work/ 与 knowledge/ 内部；style/ 是扁平风格文件，archive/ 是终态归档，不套三层
- **四选一**（入库分诊）：新货 / 补货 / 有矛盾 / 没营养。定义见 `references/ingest-basics.md`，引用时一字不差
- **三条军规**：①索引正文不写死篇数（要数字让 AI 现场数或跑脚本）②新文件只追加 Recent 流水账（一行日期+文件名+一句话）③「没营养」合法出口
- **第一天三条安全规矩**：①红线内容不入库、不进会话 ②拿不准先确认安全口径 ③推远程前确认用的是公司认可载体
- **敏感度**：🟢 可公开（公开行业文章收藏、已对外发布的内容）/ 🟡 公司工作内容（**默认级**，照常进 Git 但远程仓库必须私有、仅限工作需要的人访问、永不对外公开）/ 🔴 红线机密——不入 Git（.gitignore 排除）+ 不入索引（对 AI 不可见），最稳妥物理隔离存库外。诚实提醒：.gitignore 只管 Git，管不住 AI 读文件系统——索引规则是纪律约束，不是技术隔离
- **升级四台阶**：第 0 天最小版 / 2 周四区+敏感度+Git / 1 个月对账+体检 / 3 个月风格层+对抗审查+项目完结提炼
- **本地与云端的分工**：本地 md 是 AI 工作的输入真相源；飞书仍是公司正式文档源，两者分工不打架

## 个人库与团队知识的边界

本 skill 搭的是**个人工作上下文库**——装「让 AI 更懂你的工作」的背景，不是团队知识库的替代品。边界：个人库管个人工作上下文（项目档案、方法论、风格）；需要团队共识的结论（评审拍板的方案、对外口径、沉淀文档）反同步回飞书——飞书是公司正式文档源，个人库是 AI 工作的输入层，两者不打架。反同步是外发动作，走「提议→确认」并遵守安全口径。

## 会话开场

进入用户库所在目录工作时，开场先做两件事（都不用请示）：

1. 读根索引 AGENTS.md，重点是 Recent 区——用一句话回应用户「上次我们做到哪了」
2. 顺手检查成长触发条件（文件 > 30 / 用满 2 周 / Recent 满 20 / 用户抱怨难找 / 出现疑似红线内容），命中就提一句升级建议，说完即止

用户库根索引自带开场动作时，以库内索引为准——库的规矩优先于本 skill 的默认动作。

## 跨工具兼容

知识库底座（文件夹 + Markdown + AGENTS.md 索引）与 AI 工具解耦，换工具不换库：

- `AGENTS.md` 是开放事实标准（由 Linux 基金会托管），OpenCode / Claude Code / Cursor / Codex 等主流 AI 编码工具原生支持——一律生成 AGENTS.md，可移植性最好
- 个别工具只认自家配置文件（如旧版 Cursor 的 .cursorrules）：让 AI 做一份同内容副本即可，源头仍以 AGENTS.md 为准
- 本 skill 本身放进对应工具的 skills 目录即可生效（如 `~/.claude/skills/`，多数工具兼容该格式）；推荐工具与替代选项在 Mode 1 手册 Step 0 给出，保持工具中立
- 用户问「XX 工具行不行」：判断标准就一条——能对话、能读写本地文件（外加一条公司前提：公司许可口径允许用）。行就用，不行换

## 执行自查（每次任务收尾前过一遍）

1. 这次动作产生的新文件，是否全部登记进了索引（含 Recent 区）
2. 是否动了不该动的——删除、覆盖、批量移动有没有走「提议→确认」
3. 索引里有没有被写入「共 N 篇」式计数
4. 引用四选一、敏感度、四台阶、安全规矩时，口径是否与「统一口径」一致
5. 是否触碰安全红线——红线内容进了库或会话、外发动作没确认公司口径，发现立即提醒用户处理
6. 用户是小白——这次解释里有没有未解释就使用的术语

自查全过再宣布完成——少一步就是没完成。

## FAQ（用户常问）

- **搭完最小版要多久？** 30 分钟左右。后续各级升级 30-60 分钟，且每级独立可用，随时停下
- **公司电脑 / 公司网络能用吗？** 动手前先确认公司对外部 AI 工具与外部仓库的许可口径（装机权限、网络可达性、是否收费）——有限制就用公司认可的替代选项；库推远程时，公司内网 GitLab 等公司载体优先
- **库建在哪个盘都行吗？** 行，但建议非系统盘、路径纯英文且不含空格（如 `D:\my-kos`）最稳；坚持用中文路径多数工具也能跑，但个别脚本可能乱码，AI 会提示风险、你拍板——重装系统也不殃及池鱼
- **我的笔记都在飞书 / 云笔记 / 微信收藏里，要先全部搬过来吗？** 不用。Mode 1 访谈时告诉 AI 有什么就行；日常用得到的批次复制粘贴进库，其余用到再搬。本地 md 是 AI 工作的输入真相源，飞书仍是公司正式文档源，两边分工不打架
- **这个库和团队的飞书文档库什么关系？** 个人库管个人工作上下文，是 AI 工作的输入层；团队共识结论（评审拍板的方案、对外口径、沉淀文档）反同步回飞书——飞书是公司正式文档源。两者不打架，详见「个人库与团队知识的边界」
- **要不要先装个笔记软件当底座？** 不用。库 = 文件夹 + Markdown + AGENTS.md。笔记软件只是给人看的浏览层，AI 只认文件夹
- **换一个 AI 工具，库还在吗？** 在。AGENTS.md 是开放标准，主流工具都认（见上方「跨工具兼容」）——换工具不换库
- **这个 skill 和 context-engineer 什么关系？** kos-starter 管起步和成长路径；context-engineer 管单项目/团队级的深度 context 工程。先用本 skill 起步，长大了配合用
- **中途换电脑怎么办？** 库就是个文件夹。最小版直接整目录拷贝；上了 Git（台阶 2）之后 clone 即完整恢复——图片不入 Git，通过公司认可的方式单独同步图片目录。这正是台阶 2 存在的理由之一

## 边界与让位

- 本 skill 只做三件事：起步引导（BUILD）、日常轻量托管（USE）、阶段性升级（GROW），不做全功能知识库管家
- 用户成长到需要单项目/团队级的深度 context 管理时，主动推荐配合 context-engineer 使用（GitHub 搜 LeeFinn2025/context-engineer）：kos-starter 管起步和成长，context-engineer 管深耕，两者不冲突
- 引导过程保持克制：AI 提议、用户决定。库是用户的，AI 只是管家
