# build-guide — Mode 1 BUILD 搭建引导（30 分钟完成骨架与种子访谈）

> 目标：带用户 30 分钟完成骨架与种子访谈（当天可用；含装工具首日全程约 1 小时）——直接搭出完整四区结构：目录 + 各级索引 + Git + 远程载体 + 种子文档（工作档案与风格三件套），收尾对账验收。工具与 skill 的安装不是本手册的事（见各自官方说明），手册从「用户已在 AI 工具里打开目标目录」开始。
> 节奏：对话式引导，一次只推进一个 Step，确认完成再进下一个。别把六个 Step 一次性倒给用户。

## 时间盒（总 ≤30 分钟）

| Step | 内容 | 建议用时 |
|---|---|---|
| 0 | 前置确认（目录就位 + 安全边界 + 远程载体口径） | 3 分钟 |
| 1 | 建骨架（四区 + 索引 + Git） | 8 分钟 |
| 2 | 种子访谈（5~8 问 + 可选写作样本） | 10 分钟 |
| 3 | 挂载预置内容包（可选） | 3 分钟 |
| 4 | 收尾（对账 + 规矩确认 + 首次 commit） | 3 分钟 |
| 5 | 验收（四项测试） | 3 分钟 |

超时信号：访谈超过 12 分钟还在问，说明问得太细——收住，剩下的交给日常入库慢慢长。

## Step 0 前置确认：目录、安全边界与远程载体口径

开场白示例（可照抄可改写）：「接下来 30 分钟，我带你搭一个完整的工作知识库——四区结构一次到位，搭完当天可用，你不用每次都给我从头介绍自己的岗位和项目。动手前先确认三件事。」

1. **目录就位**：会话当前工作目录就是知识库根（或其父目录）。还没有文件夹的，现在定：建议**非系统盘**、路径**纯英文且不含空格**（如 `D:\my-kos`），命名简短英文；用户坚持中文路径时如实提示个别工具/脚本可能乱码，接受其选择并在脚本环节显式处理编码。Windows / macOS 都一样：文件管理器 / Finder 里右键新建，或让 AI 代建——代建后必须回显完整路径让用户确认
2. **安全边界（主动告知，不等用户问）**：库文件本身不出你的电脑，但 AI 读库意味着**内容会随会话发送给它背后的模型服务商——会话本身不保密**。红线内容（密码密钥、证件号码、薪酬信息、未公开的合作与商务条款、所在组织规定的保密信息等）不入库、不进会话；拿不准某类内容能不能用 AI 处理，先确认安全口径再动手
3. **远程载体口径**：库今天就要上 Git，远程用哪个载体现在定——**工作场景用组织认可载体**（内网 GitLab / 组织指定仓库，确认有建仓/推送权限）；**个人场景用私有仓库**（GitHub / Gitee 等平台的 Private 仓库）。在公司或组织的设备/网络使用的，先确认组织对外部工具与仓库的许可口径——拿不准先问（默认顺序：直属主管 → IT/信息安全），不要先斩后奏。本机 Git 可用性顺手验一下：终端跑 `git --version` 有版本号即可；没有就先装，或如实告知可先纯本地、远程后补（无异地备份，机器故障即丢）

Why：目录和安全边界先立住，搭出来的库不用推倒重来；载体口径先确认，第一次推送就不会推错地方。

## Step 1 建骨架：四区 + 索引 + Git（8 分钟）

**四区一览**：

| 区 | 装什么 | 特点 |
|---|---|---|
| `work/{{产品线}}/` | 项目工作 | 按产品线隔离，项目完结整体归档 |
| `knowledge/` | 方法论、设计规范、竞品档案、行业认知 | 跨项目复用 |
| `style/` | 你的思维/表达/审美偏好 | AI 分身风格种子，始终加载（Step 2 访谈填充） |
| `archive/` | 完结项目的整体归档 | 终态冻结，不套三层；方法论精华提炼入 knowledge/ |

三层生命周期（`drafts/` → `workspace/` → `context/`，知识只升不降）只套在 `work/` 与 `knowledge/` 内部；`style/` 是扁平风格文件，`archive/` 是终态归档。

**待启用机制（核心纪律：不造假空目录）**：只建当前有内容的目录；暂无内容的分区在根索引标「待启用」，内容到了再建——结构统一，不造空架子装样子。

**操作**：

1. 问一句「你现在手头有什么内容要先放进来」，决定启用哪些分区：一般第一天启用 `knowledge/`（Step 2 的工作档案落这里）和 `style/`（Step 2 的风格三件套落这里）；`work/` 有进行中项目就建对应产品线子目录，没有就标待启用；`archive/` 一般标待启用
2. 用 `templates/AGENTS-root.md` 生成根索引：替换全部 `{{占位符}}`（路由表里的产品线名、各分区状态改「已启用/待启用」），保留三条军规 + 三条安全规矩 + 索引规则 + Recent 区，别自作主张删
3. 每个已启用的内容分区配一份子索引（`templates/AGENTS-sub.md`，work/{产品线} 与 knowledge 两形态择一），同样替换占位符
4. `git init` + 写 `.gitignore`（排除红线与图片）+ 关联 Step 0 定的远程载体。`.gitignore` 示例：

   ```gitignore
   # 🔴 红线内容，永不进 Git（同时不入索引；最稳妥存库外）
   **/_private/
   # 图片不入 Git——防止仓库被撑爆，换机走认可方式单独同步
   **/assets/
   ```

5. Git 命令 AI 代跑或给命令让用户粘贴执行均可；push 是外发动作——**提议→用户确认载体无误后再推**；当天不推也行，如实提醒「无异地备份，机器故障即丢」

**Why**：结构一次到位（后续不用改造），但目录跟着内容长（不造假空目录）——两者靠「待启用」机制兼顾。Git 第一天就启用：每次修改可回滚，换机不丢。

## Step 2 种子访谈（核心步骤，10 分钟）

目的：从用户脑子里提取高频工作上下文。这些问题的答案，就是未来 AI 最常读的背景资料——也是用户过去无数次向 AI 重复解释过的东西。原则：**你的大脑是初始事实的唯一来源**——AI 只做结构化整理，不编造通用内容。

5~8 个问题示例（按需挑选改写，别照本宣科）：

1. 你是谁？在什么岗位、负责什么产品线？（角色 + 职能 + 产品线，未来每篇产出的前提）
2. 你过去几年做过什么项目？（项目历程是背景文件的骨架）
3. 你平时用 AI 干什么？（写方案 / 做分析 / 写周报……决定库的重心）
4. 你最常向 AI 重复解释的背景是什么？（这是 ROI 最高的入库内容，优先追问细节）
5. 你手头有什么现成文档？（周报、邮件、评审意见、收藏的行业文章——都是现成种子）
6. 你想先管哪一块？（先聚焦一条产品线或一类知识，别贪全）
7. （可选）你说话、写东西有什么习惯或偏好？（风格三件套的素材）
8. （可选）有哪些红线内容需要绝对隔离？（为敏感度执行埋种子——问这个是为了防，不是为了存：红线内容不入库不进会话）

问题优先级：4 > 1 > 5 > 2 > 3 > 6 > 7/8。时间不够先砍可选项，问题 4（重复解释的背景）无论如何要问到。

追问示例（针对问题 4）：用户说「老是要解释我是做什么的」→ 追问「如果给新同事发一段 200 字的自我介绍，你会怎么写？」——这段话就是未来背景文件的雏形，原样记下来。

**可选写作样本**：用户有既有写作样本（周报、邮件、评审意见）就喂给 AI，提炼表达习惯和决策偏好，风格三件套会更准；没有样本就靠问题 7 的口头描述。

**落盘产物**（访谈记录先给用户过目，确认后再写入）：

| 产物 | 落位 | 说明 |
|---|---|---|
| 工作档案 profile.md（岗位与产品线背景、项目历程、常用方法论） | `knowledge/context/` | 跨项目复用的个人工作背景 |
| 风格三件套 thinking.md / communication.md / taste.md | `style/` | 怎么想问题 / 怎么说话 / 什么是好 |

**访谈纪律**：

- 一次只问 2-3 个问题，不轰炸；答完一批再问下一批
- 用户答不上来的直接跳过——库会长出来，不必一次填满
- 记原话，别急着替用户归纳；用户的话和 AI 的推断分开记
- **风格文件 AI 提议后须用户确认才写入，绝不自动生成风格画像**；生成后请用户通读一遍，删掉 AI 脑补的内容，只留认可的
- 每个新文件登记进对应目录的索引（子索引清单或 Recent 区）——清单里挂空名，背景测试必失败

## Step 3 挂载预置内容包（可选，3 分钟）

问用户：「**你是否有团队/组织分发的预置内容包文件夹？**」（预置内容包 = 团队统一分发的模板与规范集合，如文档模板、工作流说明，走组织内部分发渠道获取）

- **有** → 让用户提供包的路径，然后：
  1. 读包内 `manifest.md`（包的清单与说明——列了包里有什么、各自装到哪）
  2. 按包内 README 的指引挂载：把模板/内容复制到对应目录，逐项登记索引
  3. **包内模板与本 skill 通用模板同名时，以包内为准**（覆盖通用模板）
  4. Recent 区登记一行本次挂载
  5. manifest 缺失或结构与说明对不上：如实告知，请用户找分发方确认，不瞎猜硬装
- **没有** → 跳过，说一句「不影响任何功能，以后拿到包随时可以补挂」
- **后补挂载**：已建好的库，用户拿到包后说「挂载预置内容包」，走同一流程

本 skill 不内置任何预置包内容——包是组织分发的实体，skill 只负责挂载。

## Step 4 收尾：对账 + 规矩确认 + 首次 commit（3 分钟）

1. **对账脚本**：**已挂载含对账脚本的预置内容包时，直接复用包内脚本（如 `scripts/Check-KOSIndex.ps1`，用法见包内说明），不必现写**；没有包才让 AI 现场写一个只读检查脚本（语言不限，用户环境能跑即可；写法与自检详见 `references/maintain-guide.md`），BUILD 时至少核对：①索引列的文件都存在 ②存在的文件都在索引里。**脚本自检**：临时造两个测试项——库里放 1 个不登记索引的孤儿文件，索引里写 1 个不存在的文件名——跑一遍，两项应双双出现在报告里；验证通过删掉测试项。脚本存进库（如 `tools/` 目录）并登记索引，之后复用
2. **规矩确认**：逐条读出根索引里的三条安全规矩（①红线内容不入库、不进会话 ②拿不准先确认安全口径 ③推远程前确认用的是认可载体（工作场景）/私有仓库（个人场景））和三条军规（索引不写死篇数 / 只追加 Recent / 没营养合法出口），确认原文在、一字未删
3. **首次 commit**：把建库产物全部提交（git add + commit 由 AI 代跑或给命令用户粘贴）；远程载体已确认的，提议 push——用户点头再推
4. **Recent 登记**：根索引 Recent 区记一行「建库——四区骨架 + 种子访谈产物落盘」

**产物检查清单**（逐项过，任何一项不过当场补）：

- [ ] 已启用分区目录存在且有真实内容；未启用分区在根索引标「待启用」，无空目录
- [ ] 根索引按 `templates/AGENTS-root.md` 生成，全部 `{{占位符}}` 已替换，三条军规 + 三条安全规矩原文在
- [ ] 已启用分区各有一份子索引；种子文档（工作档案 + 风格三件套）已落盘并登记
- [ ] `git init` 完成，`.gitignore` 含 `**/_private/` 与 `**/assets/`
- [ ] 对账脚本跑通且经过自检
- [ ] Recent 区至少 1 条真实登记

## Step 5 验收（四项全过才算搭完）

1. **背景测试**：最好新开一个对话（老会话里 AI 记得访谈内容，测不出索引效果），问 AI「我是做什么的」。AI 只凭根索引和库内文件回答正确 = 通过。不方便开新会话，就要求 AI 明确「只根据 AGENTS.md 和库内文件」作答
2. **入库测试**：说一次「记录这个 + 任意一段内容」，AI 应走完：红线预拦 → 四选一分诊声明 → 落位 → 登记 Recent → 一句话确认（流程定义在 `references/ingest-basics.md`，做这项测试前先读它）
3. **对账通过**：脚本报告零发现项（或发现项已当场修复并复跑）
4. **红线零入库**：抽查本次访谈产物与入库测试素材（合计 5 条左右），无红线内容——有就当场移出库并提醒确认安全口径

任何一项失败，按表排查，修完重测：

| 症状 | 常见原因 | 修法 |
|---|---|---|
| AI 答不出「我是做什么的」 | 背景没落成库内文件，或落了没登记索引 | 把关键背景写成文件并登记进清单 |
| AI 答错方向 | 索引说明与文件实际内容不符 | 改索引说明，以文件内容为准 |
| 入库测试没走四选一 | 根索引规矩区缺了分诊条款 | 补上「记录这个→先报四选一」条款 |
| 对账报不一致 | 建库过程中漏登记 | 按报告补登记或修索引 |

Why：闭环验证的是「AI 真的从库里读到你了」，这是整个知识库存在的意义。

收尾时给用户回顾今天的产物（各一句话），并交接日常用法：

1. 一个四区骨架的知识库文件夹（路径：{{xxx}}），暂无内容的分区在索引里标了「待启用」
2. 根索引 + 子索引——AI 认识你的入口
3. 种子文档——工作档案与风格三件套，都经你确认过
4. Git 已启用——每次修改可回滚，远程载体已关联（或待推）
5. 通过四项验收的活库——从现在起，你说「记录这个」它就长大

**日常怎么用**：想存东西就说「记录这个」「保存这个」；想干活直接说任务（「xx 产品线的需求分析」「写一份竞品分析」「写周报」），AI 会先读根索引再动手。库该养护的信号（文件超 30、Recent 满 20、找东西难、疑似红线）出现时，AI 会主动提醒你说「体检」。

## 既有库的续建与改造

用户已有文件夹或旧库时，不推倒重来，按中断点接走：

| 现状 | 接走方式 |
|---|---|
| 无文件夹 | 从 Step 0 开始 |
| 有文件夹，无 AGENTS.md | 从 Step 1 开始（现有文件在 Step 1/2 一并盘点归位） |
| 有 AGENTS.md 的平铺旧库（单层目录、无四区） | 四区归类改造：按 Step 1 建骨架，现有文件逐个问「属于哪个区」挪入（拿不准进对应区 drafts/），用 `templates/AGENTS-root.md` 重写根索引，Git 未启用的补 init |
| 有 AGENTS.md，未过验收 | 从 Step 4 收尾开始补对账与验收 |

**迁移对照示例**（改造时 AI 逐文件带着用户过，每问一次「这个去哪」）：

| 现有文件 | 去处 | 依据 |
|---|---|---|
| profile.md（岗位与项目背景） | `knowledge/context/` | 跨项目复用的个人工作背景 |
| methods/ 下的方法论笔记 | `knowledge/context/`（一个文件一个领域） | 通用知识，跨项目复用 |
| notes/ 里的行业文章、竞品素材 | `knowledge/drafts/`，消化后升 context | 通用知识，拿不准先进 drafts |
| {{某产品线}}的项目笔记、方案素材 | `work/{{产品线}}/drafts/` | 项目工作，按产品线隔离 |
| 读了还没消化的收藏 | `knowledge/drafts/` | 拿不准进 drafts |

改造原则：内容比结构重要——现有文件按区归类挪进去，不推倒重来、不改写内容。旧索引的 Recent 记录保留进新根索引尾部——搬家不丢账。

## 常见卡点与解法

| 用户说 | 实际情况 | 解法 |
|---|---|---|
| 「我不知道有什么可存的」 | 没意识到自己的背景就是资产 | 从「最近一次向 AI 重复解释的事」入手——那件事就是第一篇 |
| 「我的笔记在飞书 / 云笔记 / 微信收藏里」 | 存量都在别处 | 不强制迁移。先建库，日常用到的复制粘贴进来，用到再搬；本地 md 是 AI 工作的输入真相源，团队平台仍是团队正式文档源，两边分工不打架 |
| 「公司或组织的电脑能装这些工具吗」 | 装机权限 / 许可口径未确认 | 装工具阶段就要确认（不是本 skill 的事）；库推远程按 Step 0 第 3 条的载体口径走，受限就用组织认可的替代选项 |
| 「这些东西放本地安全吗」 | 担心泄密 | 如实说：库文件只在你电脑上，但 AI 读库意味着内容会随会话发送给它背后的模型服务商，会话本身不保密——红线内容别入库别进会话，拿不准先确认安全口径；「不入索引」是纪律约束，管不了会话传输 |
| 「能不能直接帮我建一堆目录」 | 想要结构感 | 拒绝空目录。待启用机制就是为此设计：结构在索引里认位，内容到了再建——内容比结构重要 |
| 「这和团队的文档库什么关系」 | 混淆个人库与团队知识库 | 个人库管个人工作上下文，是 AI 工作的输入层；团队共识结论回流到团队平台。两者不打架 |
| 「我平时用手机 / 平板」 | 没有桌面 AI 工具 | 本方案依赖能读写本地文件的工具，先在电脑上搭；移动端以后当浏览入口 |
