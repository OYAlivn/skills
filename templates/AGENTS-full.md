## 系统架构：五域 × 三层 × 敏感度

```
维度1：领域（Domain）—— 按人生角色分顶层目录
  work/       工作（按公司隔离，阶段性）
  personal/   个人资产（跨公司持续积累）
  ventures/   副业（独立持续）
  style/      风格层（AI 人格种子，始终加载）
  archive/    归档（离职/完结后的脱敏精华）

维度2：生命周期（Lifecycle）—— 每个领域内部三层
  context/    已确认的事实
  workspace/  进行中的工作
  drafts/     想法和素材
  知识单向流动：drafts/ → workspace/ → context/，拿不准进 drafts/

维度3：敏感度（Sensitivity）—— 提交范围控制
  🟢 脱敏后可公开 / 🟡 仅私有远程 / 🔴 永不进 Git
```

## AI 行动规则（最优先执行）

### 1. 会话开始必做

- 读 `style/` 三个文件（thinking.md / communication.md / taste.md）加载主风格——**style/ 始终加载，无论什么任务**（文件尚未创建时跳过此步，不报错；升级台阶 4 时填充）
- 读根索引 Recent 区，一句话了解最近动态

### 2. 索引规则（硬约束）

- Read 任何 .md 文件前，先检查父目录的 AGENTS.md 是否索引了它
- 未索引的文件视为「不可见」——不读、不引用、不基于其内容回答
- 「已索引」的两种合法形态：**逐文件索引**（curated 白名单，仅列出者可见）；**目录级索引**（目录行声明整目录可见，AI 可在该目录内自由检索）
- 索引正文不写死文件计数；要数字现场数或跑对账脚本
- 新增 / 删除文件必须同步更新父目录 AGENTS.md；新文件在 Recent 区追加登记
- 越往上层越抽象（全局规则），越往下层越具体（文件清单）

### 3. 敏感度红线

| 敏感度 | 含义 | AI 行为约束 |
|---|---|---|
| 🟢 | 脱敏后可公开 | 正常读写，可对外输出 |
| 🟡 | 仅私有远程仓库，禁公开展示 | 可读写、可提交私有远程；禁止任何公开渠道输出；超敏感的 🟡（求职、台账类）可进一步 gitignore 本地化 |
| 🔴 | 永不进 Git | 永不输出到对外渠道；写入前二次确认目标文件敏感度 |

禁止跨级污染：🟡/🔴 内容不得写入 🟢 文件，🔴 内容不得写入 🟡 文件。

### 4. 动作纪律

- 重要动作提议 → 用户确认再执行；删除、git 推送、批量移动、覆盖类必须先问
- 基于库回答问题默认只读；高价值新理解提议回填，用户点头才写
- 工作内容迁移到 personal/ventures/ 时脱敏：去公司名、去内部数据、去内部术语

### 5. 入库纪律（「记录这个」类存储指令的硬约束）

- 动手前先报**四选一**分诊：新货（库里没有同主题，走完整入库）/ 补货（已有同主题，更新旧文件或新增+交叉引用）/ 有矛盾（与库内结论冲突，双方都留+就地标注「待裁决」，Recent 同步记一行）/ 没营养（无实质价值，只存原文+记一笔——这是合法出口，绝不强行整理）
- 新文件只追加 Recent 区（一行日期+文件名+一句话），不改正文清单；攒满 20 条提醒用户收编
- 索引正文不写死文件计数，要数字现场数或跑对账脚本

## 知识流动（单向提炼）

知识在各领域产生，向上提炼到个人层和风格层，不反向流动：

```
work/{{公司}}/ ──(离职提炼)──► archive/{{公司}}-essence.md ──(汇入)──► personal/ 履历
work/{{公司}}/ ──(持续提炼)──► personal/ 技能文件
ventures/ ──(持续提炼)──► personal/ 技能文件
所有领域 ──(风格特征)──► style/*.md
```

提炼一律先提议、用户确认再执行，并遵守脱敏原则。

## 文档规范

- 命名：持久内容用 `{topic}.md`（如 profile.md）；时间相关用 `{date}-{topic}.md`（如 2026-01-15-周会.md）
- 图片：存 `assets/{文档标识}/`，命名 `{章节关键词}-{序号}.png`，不散放在 assets/ 外
- 内部链接用标准 Markdown 相对路径；重命名 / 移动文件前先查引用并同步更新索引与正文链接
