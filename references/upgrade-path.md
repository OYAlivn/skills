# upgrade-path — Mode 3 GROW 升级路径 + 体检

> 触发：「升级知识库」「体检」「知识库乱了」，或 Mode 2 的成长触发条件命中。
> 原则：四个台阶每一步都独立可用，随时停下。升级是「把现有内容归类挪进更好的结构」，不是推倒重来。

## 台阶总览

| 时点 | 做什么 | 本章位置 |
|---|---|---|
| 第 0 天（30 分钟） | 最小版：文件夹 + 根索引 + AI 工具 | ✅ 已建成（Mode 1） |
| 用 2 周后 | 五域目录 + 敏感度分级 + Git 私有仓库 | 台阶 1 + 台阶 2 |
| 用 1 个月后 | 对账脚本 + 事件驱动对账 + 30 天体检 | 台阶 3 |
| 用 3 个月后 | 风格层三件套 + 双 AI 对抗审查 + 离职提炼 | 台阶 4 |

时间点是建议值，实际以成长触发条件为准（文件 > 30 / 用满 2 周 / Recent 满 20 / 抱怨找东西难 / 出现敏感内容）。用户喊「升级」时，先对照此表定位当前在哪级，缺哪级补哪级，不跳级。用户问「我该升级吗」：先报四台阶位置，再问一句「最近找东西费劲吗」——体感比日历准。各级台阶之间，日常照旧走 Mode 2 入库——升级是一次性动作，不改变日常习惯。

## 升级前检查清单（每级台阶动手前过一遍）

- [ ] Recent 区已收编（攒满 20 条的先收进正文清单）
- [ ] 没有未登记的孤儿文件（有就先补登记）
- [ ] 已用 Git 的话先 commit 一次——升级是重大变更，要有回滚点
- [ ] 与上一台阶的间隔够（对照总览表，不跳级）

## 台阶 1：五域改造（约 1 小时）

**什么时候值得做**：一个平铺文件夹开始装不下你的人生角色——工作笔记和副业灵感混在一起、个人资料和工作文档互相污染时。不值得做：文件不多、主题单一，最小版够用就别动。

**五域一览**：

| 域 | 装什么 | 特点 |
|---|---|---|
| `work/{{公司}}/` | 工作内容 | 按公司隔离，换工作整体归档 |
| `personal/` | 职业经历、技能、简历 | 跨公司永久 |
| `ventures/` | 副业（公众号、小红书等） | 独立持续 |
| `style/` | 你的思维/表达/审美偏好 | AI 人格种子，始终加载（台阶 4 才填充内容） |
| `archive/` | 离职/完结后的脱敏精华 | 只进提炼物，不进原始文件 |

五域不是齐步走：先建你用得着的域，其余留目录 + 一行种子索引，内容长出来再填。

**改造原则：内容比结构重要**——现有文件按域归类挪进去，不推倒重来、不改写内容。暂时为空的域留目录 + 一行种子索引即可，不造空架子装样子。

**操作**：

1. 盘点现有文件，逐个问「这属于哪个域」；拿不准的进该域 drafts 类目录
2. 用 `templates/AGENTS-full.md` 重写根索引，替换全部 `{{占位符}}`
3. 每个域建一份 AGENTS.md 子索引（结构参考根索引，越往下越具体：文件清单、域内规矩）
4. 挪动完成 → 逐域核对（索引列的 vs 实际存在的）→ Recent 登记本次改造

**迁移对照示例**（AI 逐文件带着用户过，每问一次「这个去哪」）：

| 现有文件 | 去处 | 依据 |
|---|---|---|
| 简历、技能方法论笔记 | `personal/` | 跨公司资产 |
| {{A公司}}的项目笔记 | `work/{{A公司}}/` | 按公司隔离 |
| {{公众号}}选题库 | `ventures/` | 副业内容 |
| 读了还没消化的收藏 | 对应域的 `drafts/` | 拿不准进 drafts |

## 台阶 2：敏感度 + Git（约 30 分钟）

**三级定义（统一口径）**：

| 级别 | 含义 | 落地 |
|---|---|---|
| 🟢 | 脱敏后可公开 | 正常进 Git，可推远程 |
| 🟡 | 仅私有远程 | 照常进 Git，但远程必须私有、永不公开；更敏感的（求职、台账类）可再 gitignore 本地化 |
| 🔴 | 永不进 Git | `.gitignore` 排除，仅存本地 |

**操作**：

1. `git init`（初始化版本管理，让这个文件夹开始被 Git 跟踪）；在 GitHub / Gitee（代码托管平台，相当于你的免费私有云盘）建**私有**远程仓库并关联推送（push = 把本地记录上传到远程备份）
2. 写 `.gitignore`（告诉 Git「这些文件永远别跟踪」的排除清单），示例几行：

   ```gitignore
   # 🔴 永不进 Git
   **/_private/
   # 🟡 超敏感，仅本地
   personal/workspace/求职/
   ```

3. 库内现有文件过一遍敏感度逐个标级；出现工资、证件号、密码类内容一律归 🔴
4. 首次 commit + push，验证在另一台电脑能完整恢复

**内容默认分级速查**（拿不准时问用户，不替用户定密级）：

| 内容 | 默认级别 |
|---|---|
| 个人技能方法论、已公开的文章 | 🟢 |
| 工作文档、项目细节 | 🟡 |
| 求职材料、薪资台账 | 🟡（建议再 gitignore 本地化） |
| 证件号、密码、日记类 | 🔴 |

Push 前确认远程仓库是 Private——这步省了，后面全白做。

Why：Git 是后悔药（每次修改可回滚、搞砸可回退）+ 换机不丢。私有远程是底线——公开仓库一次误推就是事故，且互联网有记忆。

## 台阶 3：对账脚本 + 30 天体检

**对账脚本（让 AI 现场写）**：让 AI 当场写一个只读检查脚本，语言不限（用户环境能跑即可，PowerShell / Python / Bash 都行），核对四件事：

1. 索引列的文件都存在
2. 存在的文件都在索引里
3. 断链：索引或正文引用了不存在的文件
4. 孤儿引用：没有任何索引指向的文件

脚本只输出报告，不改任何文件——修不修、怎么修，人决定。脚本存进库（如 `tools/` 目录）并登记索引，之后复用。

**脚本自检（写完必做，防误报漏报）**：临时造两个测试项——库里放 1 个不登记索引的孤儿文件，索引里写 1 个不存在的文件名——跑一遍脚本，两项应双双出现在报告里；验证通过后删掉测试项。小白没有代码审计能力，这步就是脚本的可信度证明——拿着未经自检的报告去「当场修」，比不修还危险。

**事件驱动对账**：每批操作（入库、迁移、清理）收尾时跑一遍脚本，发现项当场修。不攒大扫除——攒到月底的账没人对。

**30 天体检（两层）**：

- 结构层：跑对账脚本，看报告处理发现项
- 内容层：人工 + AI 一起过——过时结论、前后矛盾、断链积压、该晋升没晋升的 drafts；重点检查 AI 最常读的入口文件（根索引、profile 类背景文件），它们错了后面全错

**体检报告骨架**（每次体检按此出，发现项写「实际结果」，不许报喜不报忧）：

    # 知识库体检报告 {日期}
    ## 结构层（对账脚本输出）
    - 索引↔文件不一致：{条数+明细}
    - 断链 / 孤儿引用：{条数+明细}
    ## 内容层
    - 过时结论：{文件+具体位置}
    - 前后矛盾：{文件对}
    - 积压 drafts：{文件+放了多久}
    - 入口文件（根索引 / profile）状态：{一句话}
    ## 建议动作
    - {按优先级列动作}

Why：凡是手工记账必然漂移。对账的本质是守住「单一事实源」：索引说有什么，磁盘上就有什么，AI 读到的和实际存在的一致。

## 台阶 4：进阶机制（每个独立可用，按需启用）

**双 AI 对抗审查**（何时用：重要方案、文档定稿前）
让两个立场相反的 AI 各审一遍：正方验证目标是否达成、逻辑是否自洽；反方专职挑刺找漏洞、找反例。两边结论交叉看再定稿。实现方式：两个不同工具，或同一工具的两个会话（一个指令「验证它」，一个指令「推翻它」）。不必事事双审——日常笔记和随手存档单 AI 足够，双审留给要发给别人的东西。

**风格层**（何时用：想让 AI「像你一样」说话做事）
把决策习惯、表达偏好、审美标准写成 `style/` 下三个文件：`thinking.md`（怎么想问题）、`communication.md`（怎么说话）、`taste.md`（什么是好）。根索引声明「style/ 始终加载」。
流程五步：①喂样本（你的周报、文章、聊天记录）→ ②AI 提炼特征（决策模式 / 表达习惯 / 审美倾向）→ ③AI 提议具体条目 → ④你逐条确认，删掉不认可的 → ⑤写入并登记索引。绝不自动生成人格——每一条都得你点头。

**离职提炼**（何时用：换工作、项目完结时）
把 `work/{{公司}}/` 提炼成脱敏精华（去公司名、去内部数据、去内部术语）放入 `archive/`，可迁移的方法论汇入 `personal/` 的履历与技能文件。这是知识库对个人职业生涯最大的复利——每段经历结束都变成可携带的资产。提炼前先 commit 一次原始 `work/` 域——归档是复制提炼，原始内容不销毁。

## 台阶收尾动作（每级做完必做）

1. Recent 登记本次升级（一行：日期 + 台阶名 + 一句话）
2. 有 Git 则 commit——升级值得一个存档点
3. 已有对账脚本（台阶 3 起）就跑一遍；更早的台阶手工逐域核对
4. 重做一次 Mode 1 Step 5 的背景测试——升级不能把「AI 认识你」弄丢
