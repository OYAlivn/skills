# ingest-basics — Mode 2 USE 日常入库

> 触发：用户说「记录这个」「保存这个」「存到知识库」，或粘贴内容并表达存储意图。
> 原则：先分诊、再动手；每次入库走完 5 步闭环，不写到一半就停。

## 会话开场建议

每次会话开始，先读根索引（AGENTS.md）的 Recent 区，一句话了解上次动态——最近存了什么、做了什么——再响应用户。成本一句话，收益是接得上上文。示例开场：「上次你存了一篇复盘方法的文章，今天继续？」用户上来直接说任务没提库，也先把索引读了再干活——上下文不读，库等于白建。

## 标准流程（5 步）

1. **分诊四选一（先声明再动手）**：对照库内已有内容判断素材属于哪类，向用户报出判定结果和理由，再动笔
2. **按分诊落位**：新货走完整入库；补货更新旧文件或新增+交叉引用；有矛盾两个都留+就地标注；没营养只存原文
3. **更新索引**：新文件登记进父目录 AGENTS.md 的清单或 Recent 区——未索引 = AI 不可见，等于没存
4. **流水账追加**：在 Recent 区追加一行（日期+文件名+一句话），不改正文
5. **一句话确认**：告诉用户「存到了哪、按什么分诊、接下来可选什么」，收口

每步都短，但一步不能省——闭环的意义是用户永远知道自己的东西在哪。图片类素材存 `assets/{文档标识}/` 并用相对路径引用，不用绝对路径——换环境不断图。

## 四选一（统一定义，引用时一字不差）

| 分诊 | 定义 | 动作 |
|---|---|---|
| 新货 | 库里没有同主题，走完整入库 | 建新文件/目录，登记索引 |
| 补货 | 已有同主题，更新旧文件或新增+交叉引用 | 改旧文件，或建新文件并与旧文件互链 |
| 有矛盾 | 与库内结论冲突，两个都留+就地标注待用户裁决，不擅自取舍 | 双方都保留，就地标注「待裁决」，**Recent 同步记一行「待裁决」**（让下次会话开场可见，不悬挂），提示用户择期裁决 |
| 没营养 | 无实质价值，只存原文+记一笔，这是合法出口，绝不强行整理 | 存原始件 + Recent 记一行，到此为止 |

判断依据：查父目录索引清单 + Recent 区 + 主题关键词检索。新货还是补货拿不准时，按补货处理并向用户说明。

**分诊申报话术**（第一步向用户报告的格式）：

「查了库：{检索结论一句话}。这条判定为 **{分诊}**，理由是 {一句话}。计划：{落位方案}。可以吗，有异议直说。」

**边界案例判定**：

| 情形 | 判定 |
|---|---|
| 同主题，但带来新角度、新进展 | 补货（新增+交叉引用） |
| 与库内结论直接冲突（一个说东一个说西） | 有矛盾（都留+就地标注待裁决） |
| 纯情绪表达、寒暄、无信息量 | 没营养（存原文+记一笔） |
| 库里查无此主题 | 新货 |
| 拿不准新货还是补货 | 按补货处理并向用户说明 |
| 同一天多条同主题素材 | 逐条分诊，或合并一次补货，向用户说明取舍 |
| 素材本身是用户自己写的旧文档 | 按内容判定，作者身份不影响分诊 |

## 完整示例（一次标准入库）

用户：「记录这个」，粘贴一篇讲「每周复盘方法」的文章。

- AI：「查了库：notes/ 里已有你上月存的《复盘模板》，这篇讲同一主题的新方法，判定为**补货**。计划：新建 `notes/每周复盘方法.md` 存原文，开头加一行『与复盘模板.md 互为补充』，Recent 登记一行。可以吗？」
- 用户：「可以」
- AI：落盘 → Recent 追加 `- 2026-01-10 notes/每周复盘方法.md — 补货，与复盘模板互链` → 「已存好。要不要我把两篇的异同提炼成一段？你说要才做。」

这个示例体现四件事：先声明再动手、补货互链、追加不改正文、晋升类动作只提议不执行。如果判定是没营养：原文原样存进 notes/，Recent 记一行「收藏，未整理」，结束——这也是一次合格的入库。对照：同一篇若库里没有《复盘模板》，则判新货——直接建文件登记，不需要互链。

## 三条军规的日常执行细则

1. **索引不写死篇数**：登记新文件只加行，库内任何「共 N 篇」式写法都违规，发现当场删；用户问数量，现场数或建议跑对账脚本（见 `references/upgrade-path.md` 台阶 3）
2. **新文件只追加 Recent**：新增文件默认只动 Recent 区，正文清单的收编留给体检/升级时统一做——平时不碰正文，维护成本最低
3. **「没营养」合法出口**：判定没营养后不整理、不提炼、不写摘要，存原文+记一笔就完事；用户明确要求整理除外。判断口径是「有没有实质价值」，宁严勿宽——正式目录干净比全量保存重要

## 与索引形态的适配

- 最小版库（AGENTS-mini）：没有 drafts/ 目录，素材统一落 notes/ 类目录，规矩在根索引「规矩」区
- 五域版库（AGENTS-full）：按领域落位——工作内容进 `work/{{公司}}/`、副业进 `ventures/`、个人进 `personal/`，素材一律进对应域的 drafts/，拿不准进 `personal/drafts/`
- 两种形态的共同点：新文件都登记父目录索引的 Recent 区；四选一口径完全一致，结构不同不影响流程
- 最小版升级到五域版后，旧 Recent 记录保留进新根索引尾部——搬家不丢账

## 问答与入库的边界

- 用户在问问题（「我上次存的那篇讲了什么」）→ 默认只读，靠索引和库内文件回答，不写入任何东西
- 协作中产生新理解想回填库内 → 提议 + 用户确认才写；引用时原话与 AI 推断分开标注
- 判断是存储意图还是提问，看动词：说「记录 / 保存 / 存」是前者，其余默认后者

## 边界：ingest 不做晋升

- 素材进 drafts/ 或 notes 类目录即算完成，不自动往正式目录（context 类）搬
- 晋升只有两条路：用户明说（「把这篇提炼进 xx」），或 AI 提议 + 用户点头
- Why：错存的可以事后升级，污染「已确认事实」要用整个库的判断力陪葬

## 成长触发条件（命中任一 → 建议用户进 Mode 3）

- 库内文件总数 > 30
- 使用满 2 周
- Recent 区攒满 20 条（模板声明的上限——满了建议用户说「升级知识库」，走升级前检查清单里的收编步骤）
- 用户抱怨「找东西难」「又乱了」
- 出现明显敏感内容（工资、证件号、密码等）——这条命中时优先处理，建议直接进 Mode 3 台阶 2 落实敏感度分级

触发条件的检查是顺手的，不必每条入库都数一遍文件——体感优先，数字兜底。

命中时对用户说：你的库到了升级的时候，说「升级知识库」我带你走下一步（执行手册见 `references/upgrade-path.md`）。建议即可，不催不代决定。

## 常见坑（AI 每次入库收尾前自查）

1. 存完文件忘登记索引——5 步没走完不算完成，收尾前把步骤数一遍
2. 流水账写进正文清单——违反军规②，新文件只进 Recent 区
3. 把「没营养」硬写成摘要——违反军规③，没营养就存原文，别手痒
4. 落完位才报分诊——违反「先声明再动手」，用户失去了否决窗口
5. 素材里的图片用了绝对路径——换环境就断图，入库前统一改相对路径

踩了坑当场告诉用户并修正——透明比完美重要。
